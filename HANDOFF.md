# HANDOFF - SHARDLIGHT

Read this first, then `docs/STATUS.md` (what is verified) and `docs/KNOWN_ISSUES.md` (what is not).

## What this is
A Python 3.12 / pygame-ce game: eight genre "shards" (modes) joined by a walkable hub, one shared versioned save, and data-driven cross-mode "echoes". Everything (art, music, sound, worlds) is generated by code; content is JSON under `data/`; mods are data-only (`mods/sample_pack`).

| shard | genre | package |
|---|---|---|
| Cinder | action roguelike | `shardlight/modes/cinder` |
| Verdant | open-world RPG | `shardlight/modes/verdant` |
| Umbra | horror / stealth | `shardlight/modes/umbra` |
| Slipstream | racing (1-2 players) | `shardlight/modes/slipstream` |
| Concord | strategy | `shardlight/modes/concord` |
| Terrace | sandbox survival | `shardlight/modes/terrace` |
| Masks | fighting game (1-2 players) | `shardlight/modes/masks` |
| Orrery | space / civ sim | `shardlight/modes/orrery` |

Engine: `shardlight/core/` (loop, scenes, input, audio, content DB, mods, world/echoes, save, ai, nav, ui, fx). Hub/title: `shardlight/hub/`. Architecture: `docs/ARCHITECTURE.md`. The contract a mode must satisfy: `docs/MODE_CONTRACT.md`.

## State right now

The code is in the public repo `shipking-ai/shardlight` (all rights reserved). The rendered audio is git-ignored: run `tools/gen_audio.py` after cloning.

## Run it
```
.venv\Scripts\python.exe -m shardlight                 # the game (or play.bat)
.venv\Scripts\python.exe -m shardlight --mode verdant --seed 7 --no-audio
.venv\Scripts\python.exe -m pytest tests -q            # 419 tests
```
**Use `.venv\Scripts\python.exe`** (bash: `.venv/Scripts/python`). The system `python` has no numpy. In Git-Bash set `PYTHONPATH=.` for ad-hoc scripts (or `sys.path.insert(0, ".")`).

|---|---|

## Verdant map (the newest and largest shard, ~7,000 lines)
`worldgen.py` (+`landmarks.py`, `noise.py`, `tiles.py`, `worldmap.py`) builds the world from templates; `interiors.py` builds rooms and dungeons; `sim.py` is the `Game` (clock, player, economy, spawn zones, save/load); `combat.py`, `npcs.py` (schedules), `quests.py` (stage engine), `actions.py` (B-button interactions); `art.py`, `scene.py`, `screens.py`, `sfx.py` are presentation. Content kinds: `verdant.template|item|enemy|npc|quest|shop|recipe|loot` (schemas in `catalog.py`). Design notes and limits: `docs/modes/verdant.md`.

Cross-shard hooks it uses: emits `verdant.quest_completed{quest}`, `verdant.site_explored{site}`, facet via `complete_facet("verdant")` when quest `kindle_the_hollow` finishes; consumes unlocks `verdant.site.listening_stones` and `verdant.trade.beacon_caravans`. The whole echo web is tested in `tests/test_echo_web.py`.

## Conventions and gotchas
* Modes never import each other; cross-mode effects go through `World.emit` and `data/echo/spine.json`.
* All randomness is seeded via `core.rng.Rng(...).child(label)`; same seed => same world. Keep it that way (tests compare digests).
* Content is schema-validated; a bad entry is reported, not fatal. After adding a kind, register it in the mode's `register_content`.
* Core edits made by mode work are logged in `docs/CORE_CHANGES.md` (keep appending).
* SFX recipes that sum clips of different lengths must use `synth.mixdown`; the audio manager swallows recipe errors at run time, only `gen_audio.py` and the audio test reveal them.
* Shell heredocs containing apostrophes or unbalanced quotes can fail in some shells: write such files with an editor instead.
* NumPy 2: no 2-D `np.cross`.
* `shots/` is scratch (debug scripts, screenshots, logs). Safe to delete.
