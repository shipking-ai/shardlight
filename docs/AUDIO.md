# Audio design

All audio is original and generated by code (NumPy). Nothing is sampled, recorded or downloaded. `tools/gen_audio.py` renders the score and every sound effect into `assets/audio/` and writes `MANIFEST.json` (SHA-256, length, peak/RMS, seam ratio) and `docs/AUDIO_REPORT.md` (the generated per-file table).

```
python tools/gen_audio.py            # everything (about 40 s)
python tools/gen_audio.py --check    # verify files against the manifest
python tools/gen_audio.py --tracks verdant,umbra --music-only
```

## Music: ten looping tracks, three phase-locked layers each

`core/music.py` is the composition engine (scales, chords by scale-thirds with voice-leading, humanised events, instruments from `core/instruments.py`, circular-convolution reverb so tails wrap around the loop). `core/scores.py` holds the ten scores. Each track renders to `assets/audio/music/<track>/{bed,rhythm,lead}.wav`, exactly the same length, 32 seconds, 22.05 kHz 16-bit mono, and loops sample-perfectly (the tempo is quantised to whole samples per beat and tails are folded onto bar one).

The game fades layers in and out with `AudioManager.set_intensity(0..1)`: **bed** is always on (harmony, ambience), **rhythm** is pulse and percussion, **lead** is melody or tension. Verdant, for instance, raises intensity with the number of hostile creatures and at night.

| track | key / mode | metre | character |
|---|---|---|---|
| title | D dorian | 4/4 @ 60 | heroic and mysterious: brass theme over strings, timpani heartbeat, harp and choir |
| hub | F lydian | 3/4 @ 90 | brass and glass-bell waltz, flute and harp |
| cinder | E phrygian | 4/4 @ 120 | taiko and snare build over 16 bars, FM bells |
| verdant | G mixolydian | 6/8 @ 60 | plucked guitar, harp, frame drum, folk flute |
| umbra | F locrian clusters | 5/4 @ 75 | beating drones, sub heartbeat, a stopped clock |
| slipstream | A major | 4/4 @ 150 | pumping supersaw, arpeggios, four on the floor |
| concord | D major | 2/4 @ 90 | harpsichord, organ, two-voice counterpoint, march snare |
| terrace | Eb major | 4/4 @ 90 | slow guitar ostinato, hand drums, singable flute |
| masks | D in-sen | 6/4 @ 90 | taiko with silences, lute, breathy flute |
| orrery | A lydian | 7/4 @ 105 | glass pads, 4+3 clockwork pulse, celesta arpeggios |

The score's design note says a small Lens leitmotif (up a fifth, step back, lift) is stated in every track on a different instrument and in the track's own mode, so it recurs as the thread between worlds.

## Sound effects: 167 recipes

Every mode registers its effects with `core.audio.register_sfx(name, recipe)`: `cinder_*` (27), `verdant_*` (27), `terrace_*` (27), `umbra_*` (34), `masks_*`, `orrery_*`, `concord_*`, `slipstream_*` and the shared UI/pickup/coin/bell set from `core/sfxlib.py`. `gen_audio.py` renders each to `assets/audio/sfx/<name>.wav`. At run time `AudioManager` plays the file when it exists and falls back to the same recipe when it does not, so deleting `assets/audio` is safe.

Running the renderer for the first time also exposed **13 recipes that had been failing silently in game** (they summed clips of different lengths and the manager swallowed the error so as not to crash gameplay). They were fixed with `synth.mixdown`, and `gen_audio.py` now fails loudly if any recipe cannot render.

## Verification (`tests/test_audio_assets.py`)

* Manifest hashes match every file; every registered recipe has a file.
* Each track has three equal-length layers, none silent, no clipped samples, peak below -0.9 dBFS, RMS between -26 and -12 dBFS, loop seam ratio below 2 (measured 0.01-0.69; the title track is the highest at 0.69).
* Every effect is finite, 15 ms to 6 s long, with a sensible peak.
* Every track name and sound name used by the code exists; every mode's declared track exists.
* Re-rendering the Verdant score reproduces the file on disk to within one LSB.
* The audio manager loads the rendered files.

## What has *not* been verified

**No human has listened to any of it.** Quality was judged by measurement only (loop seams, clipping, spectral centroid, loudness, pitch-class adherence for tonal tracks). The leitmotif claim above is a design intent from `scores.py`, not something I have checked by ear or by test. Whether the music is *good*, the mix is balanced against effects, or a sound effect is irritating after the fiftieth repeat is an open question for a listening pass. Output was never played to a real audio device in this environment (tests use the dummy driver).

Disk use: 47 MB (30 music layers, 167 effects). The WAVs are **not stored in git** (they are regenerable and the render is deterministic): run `tools/gen_audio.py` once, or use `play.bat`, which does it on first start. CI renders them and runs `--check` on every push.
